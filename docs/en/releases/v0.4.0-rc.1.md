# ArchScope v0.4.0-rc.1

This is a **prerelease for controlled evaluation**, preparing the 0.4.0 feature
line. It includes the accumulated diagnostics, Windows HTTP and native desktop
work after 0.3.5. It is not a declaration of complete reference-tool parity or
universal production acceptance.

## Downloads and versions

| Artifact | Target |
| --- | --- |
| macOS DMG / app ZIP | Apple Silicon arm64, macOS 12+ |
| Windows installer / executable ZIP | Windows x64; WebView2 required |
| Linux DEB / RPM / raw binary archive | x64; GTK4 and WebKitGTK 6 runtime |
| archscope-docs.zip | English/Korean manuals, reference documents and repository examples |
| archscope-conformance-v1.zip | Synthetic offline conformance corpus |
| SHA256SUMS | Checksums for the attached release files |

Application/About version: **0.4.0-rc.1**. Windows numeric file version:
**0.4.0.1**. macOS bundle short version: **0.4.0**, build **4001**.
Linux package metadata uses the RC version. Windows x86 testing does not imply
an x86 installer is included in this release.

The workflow can use ad-hoc macOS signing when Developer ID/notarization
credentials are absent; notarization is conditional on configured credentials.
Windows artifacts are not Authenticode-signed by this workflow. Required
platform runtimes must already be available for offline use; the standard
Windows installer may bootstrap WebView2 if missing.

## Included work

- File-based CPU/wall/lock profiles, original py-spy/Speedscope/pprof evidence,
  canonical drilldown, source references and case-backed baseline comparison.
- Access, GC, JFR/native-memory, exceptions, multi-runtime thread dumps,
  Jennifer MSA, traces, Chrome/V8 CPU and Lighthouse analysis.
- Workspace cases, search, metric history, system/perf/limited BPF, runtime,
  database/socket, benchmark/crash, LLM/serving and CPU/GPU evidence workflows.
  Producer/version support is limited to the documented qualified inputs.
- Windows explicit-proxy HTTP/1.x capture, HAR and supported session formats,
  bounded retention, process attribution, inspectors, annotations, session
  comparison/correlation and an explicit-send Request Builder.
- Request/response body capture only where actual SEC-10 preflight permits it,
  with default-off opt-in, redaction, preview bounds and explicit missing,
  unsupported, encoded or truncated states.
- Input/result invalidation, x86 profile weight fixes, physical-unit chart/CSV
  exports, stable bounded PowerPoint summaries, accessibility fixes and the
  detailed screen-by-screen user manual.
- Repeated-import retention fixes and finite memory qualification. Historical
  growth failures remain preserved; later passing windows do not prove that
  every workload is leak-free.

## Remaining qualification

The tracker retains **T-601 REVIEW, T-611 REVIEW, T-613 PENDING, T-627 REVIEW,
T-654 TODO and T-662 TODO**. This RC does not close them.

- Transparent/WinDivert, proxy-ignoring clients, services and cross-session
  capture reach still need matching isolated native qualification.
- Vendor/foreign early-bound COM, session cookies and clean-host registration
  lifecycle remain separate from the tested automation contracts.
- Full original V7.6.4 exchange/display/export parity, actual IME composition,
  drag interactions, remaining format/body conditions, actual OS DPI/locale
  and the full result/provider/keyboard/reference matrix are incomplete.
  WebView zoom is not OS DPI coverage.
- Body-enabled Windows x64 remains subject to its actual preflight result.
  No dump, trust or security-policy bypass is provided.
- Memory results apply to pinned workloads and finite budgets. New unique or
  body-rich inputs, longer runs, remaining x86 native workloads, JS-heap versus
  OS-private attribution, real Windows disk exhaustion and power-loss recovery
  remain unqualified beyond their individual receipts.
- Actual two-GPU CUDA/NCCL distributed inference and natural nonzero-swap /
  elevated-pressure input remain unavailable. CPU/structural fixtures and
  observed zero swap do not establish those cases.
- The original independent CONDITIONAL review dispositions are preserved;
  local remediation is not a new independent PASS.

## Compatibility and validation

Existing AnalysisResult/data contract meanings remain intact. Application
prerelease comparison uses SemVer; numeric data/adapter/extension versions keep
their strict existing contract. The unchanged signed bootstrap pack permits
application versions before stable 0.4.0, so this RC remains eligible. A final
0.4.0 release needs a newly qualified compatible signed pack; the range is not
silently widened.

Release preparation runs full local Go tests/race/vet, frontend state/build,
resource/version checks and packaging checks. Hosted Engine Native, Windows
GUI smoke and all three packaging targets are checked before tag publication.
These checks do not substitute for the remaining native acceptance matrix.
