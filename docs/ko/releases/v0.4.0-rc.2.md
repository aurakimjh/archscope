# ArchScope v0.4.0-rc.2

0.4.0 기능 라인을 준비하는 **제한된 평가용 사전 릴리스**입니다.
RC1의 진단·Windows HTTP 기능에 리본 UI, 5개 언어, 후속 수정과 검증 도구를
포함합니다. 정식 버전의 전체 수용이나 원본 도구와의 완전한 동등성을 의미하지 않습니다.

## RC2 갱신 — 2026-11-19

사용자 요청에 따라 기존 RC2의 버전과 다운로드 주소를 유지하며 갱신합니다.
기존 파일을 받았다면 갱신한 파일을 다시 다운로드하세요. 버전은 0.4.0-rc.2로
같지만 앱의 소스·빌드 식별자는 바뀝니다. 최초 2026-11-17 소스
`9dc0c2390a7602125af5f53401ad3b3f70112824`와 당시 게시 근거는 보존합니다.

- Arthas/async-profiler HTML의 절대 좌표 프레임과 압축 상수·차이 좌표 데이터를
  읽으며 샘플 가중치를 보존합니다. 입력 JavaScript는 실행하지 않습니다.
- `jstack`·`jcmd Thread.print`의 반복 캡처를 한 텍스트 파일에 저장한 경우
  자동으로 분리해 멀티 덤프 분석과 해당 화면으로 전환합니다.
- GC pause·힙 툴팁에서 remark/cleanup/full 단계의 발생 시각·uptime·종류와
  측정된 pause 시간을 표시합니다. 오버레이가 꺼져 있거나 힙 값이 없어도 시간을
  확인하고 미기록 시간을 0으로 처리하지 않습니다. 힙 필드 없는 unified pause
  완료 요약도 파싱합니다.

검증용 JDK21 반복 캡처와 범위를 한정한 macOS JVM 입력 4건을 통과했습니다.
실제 Go 분석 결과를 사용하는 GC 차트는 브라우저 마우스 hover 9건을 통과했습니다.
macOS 네이티브 GC hover는 검증 창이 숨김 상태로 그려지지 않아 미검증이며,
사용자 원본 파일과 Windows 런타임 검증도 별도입니다. 아래 수용 제한은 유지합니다.

## 다운로드와 버전

| 파일 | 대상 |
|---|---|
| macOS DMG / 앱 ZIP | Apple Silicon arm64, macOS 12 이상 |
| Windows 설치 프로그램 / 실행 파일 ZIP | Windows x64, WebView2 필요 |
| Linux DEB / RPM / 실행 파일 압축 | x64, GTK4·WebKitGTK 6 런타임 필요 |
| archscope-docs.zip | 영문·한글 매뉴얼, 참고 문서와 저장소 예제 |
| archscope-conformance-v1.zip | 합성 오프라인 적합성 코퍼스 |
| SHA256SUMS | 첨부 파일의 SHA-256 체크섬 |

앱/About 표시는 **0.4.0-rc.2**, Windows 숫자 파일 버전은 **0.4.0.2**입니다.
macOS 번들 단축 버전은 **0.4.0**, 빌드 번호는 **4002**이며 Linux 패키지는
RC2 버전을 사용합니다. Windows x86 검증이 x86 설치 프로그램 제공을 의미하지 않습니다.

macOS Developer ID·공증 자격이 없으면 기존 파이프라인의 ad-hoc 서명으로
배포하며 공증은 구성된 자격에 따라 수행합니다. Windows 파일은 이 파이프라인에서
Authenticode 서명하지 않습니다. 오프라인 실행에는 플랫폼 런타임이 미리 필요하고,
일반 Windows 설치 프로그램은 WebView2가 없을 때 다운로드 설치를 시도할 수 있습니다.

## RC1 이후 변경

- 화면 폭에 대응하는 명령 그룹과 아이콘, 펼침·탭만·숨김 상태 저장을 제공하는
  컴팩트 리본 및 네이티브·HTTP 화면의 공통 명령 연결을 추가했습니다.
- 영어·한국어·일본어·중국어 간체·중국어 번체 UI를 제공하며 Windows 설정
  단축키의 중복 경로와 일부 선택 상태·언어 화면의 대비를 수정했습니다.
- Windows x64/x86에서 프로파일러 단위 7종의 실제 차트 저장과 서로 다른 파일의
  반복 가져오기를 검증했습니다. 성공 결과와 기존 실패 결과를 함께 보존합니다.
- 레이아웃 검증 JSON은 파일 쓰기를 마친 후 게시하며, 러너는 부분 JSON을
  제한 시간 안에서 다시 읽습니다. 파일 게시 중 Windows 공유 위반도 제한적으로
  재시도하며 실제 실패·잘못된 배율·로케일·타임아웃은
  계속 실패합니다. Windows 배칭 테스트의 시간 조건과 UTF-8 읽기도 정리했습니다.
- 렌더러 메모리 증가를 조사할 숫자 집계 전용 도구와 Mac·Docker 진단 결과를
  추가했습니다. 새 집계 도구의 실제 Windows 실행은 아직 남아 있습니다.

## 포함된 기능

- CPU·wall·lock 프로파일, 원본 py-spy·Speedscope·pprof 입력, 정규 드릴다운,
  원본 참조 및 케이스 기반 baseline 비교를 지원합니다.
- 접근·GC·JFR·네이티브 메모리·예외·다중 런타임 스레드 덤프, Jennifer MSA,
  트레이스, Chrome/V8 CPU와 Lighthouse 분석을 제공합니다.
- 워크스페이스 케이스·검색·시계열, system/perf/제한된 BPF, 런타임·DB·소켓,
  벤치마크·크래시·LLM 서빙·CPU/GPU 근거를 다룹니다. 생성 도구와 버전별
  지원은 각각 검증한 입력 범위로 제한합니다.
- Windows 명시적 프록시 HTTP/1.x 수집, HAR·지원 세션 형식, 보관 한도,
  프로세스 귀속, 검사 화면, 주석, 세션 비교·상관 분석과 Request Builder를 제공합니다.
- 요청·응답 본문은 실제 SEC-10 사전 검사를 통과하고 사용자가 기본 꺼짐에서
  선택한 경우에만 수집합니다. 마스킹·미리보기 한도와 누락·미지원·인코딩·잘림
  상태를 구분합니다. 화면별 사용자 매뉴얼과 오프라인 코퍼스도 포함합니다.

## 남은 검증

**T-601 REVIEW, T-611 REVIEW, T-613 PENDING, T-627 REVIEW,
T-663 REVIEW, T-664 REVIEW, T-654 TODO, T-662 TODO**를 유지합니다.

- WinDivert·투명 수집, 프록시를 무시하는 클라이언트, 서비스·다른 세션의
  수집 범위는 해당 환경의 격리된 네이티브 검증이 필요합니다.
- 외부 공급자·별도 프로세스의 early-bound COM, 세션 쿠키와 깨끗한 호스트의
  등록·해제는 이미 시험한 자동화 계약과 별개입니다.
- V7.6.4의 전체 표시·교환·내보내기 동등성, 실제 키보드·IME·드래그, 나머지
  형식·본문·provider·밀도·언어·원본 대조 및 실제 OS DPI 조합이 남아 있습니다.
  WebView 배율 시험은 OS DPI 시험이 아니며 번역·배치 검사는 원어민 검토가 아닙니다.
- Windows x64 본문 수집은 실제 preflight 결과에 종속됩니다. 이 후보판은
  OS 덤프·신뢰·보안 정책을 우회하지 않습니다.
- 일반 빌드의 고유 파일 반복 가져오기는 수신된 양쪽 메모리 검사를 통과했지만,
  **본문 포함 가져오기는 양쪽 모두 실패**했습니다. 트리 증가 기울기는
  x64 4.801MiB/회, x86 8.764MiB/회로 기존 4MiB/회 한도를 초과합니다.
  실제 Windows 할당 원인 추적 및 원인별 수정 후 일반 빌드 재검증이 필요합니다.
  JS 보관 한도·명시적 GC 진단으로 원인이나 일반 렌더러 통과를 주장하지 않습니다.
- 변경한 결과 파일 작성·읽기와 새 집계 도구의 실제 Windows 실행, 더 긴 메모리
  관측, 실제 디스크 고갈·전원 손실, 깨끗한 호스트 설치 및 RC1→RC2 실제
  업그레이드·이관은 각 근거에서 확인한 범위 외에 남아 있습니다.
- 실제 NVIDIA GPU 2개를 사용하는 CUDA/NCCL 분산 추론과 자연 상태의
  비영(非零) swap·높은 메모리 압력 근거는 여전히 필요합니다.
- 기존 독립 리뷰의 CONDITIONAL 판정은 유지합니다. 로컬 수정이나 릴리스 버전
  변경은 새로운 독립 PASS가 아닙니다.

## 호환성과 릴리스 검증

공통 AnalysisResult와 데이터·adapter·extension 계약의 의미는 유지합니다.
앱의 사전 릴리스 비교는 SemVer를 따르며 기존 서명 bootstrap 팩의 정식 0.4.0
미만 범위에 RC2가 포함됩니다. 정식 0.4.0에는 새로 검증한 호환 서명 팩이 필요하며
기존 서명 내용이나 범위를 임의로 넓히지 않습니다.

릴리스 준비에서 로컬 Go/race/vet, 프런트엔드 상태·빌드, 버전·리소스 검사를
수행하고 태그 발행 전에 호스팅 Engine Native, Windows GUI smoke와 플랫폼
3종 패키징을 확인합니다. 패키징·실행 smoke는 깨끗한 호스트의 설치·업그레이드나
남은 수용 조합을 대신하지 않습니다.
