# 기본 창에서 분석 결과를 먼저 보여주는 데스크톱 UI 설계

**설계안 · 구현 전.** 기본 1280×800 창에서 사용자가 파일을 열거나 캡처를 시작하면 첫 화면에서 바로 데이터를 읽고 선택할 수 있어야 한다. 메뉴를 접어 확보한 너비와 설명을 옮겨 확보한 높이를 표·그래프·상세 패널에 배정한다.

## 현재 구조와 변경 지점

- `main.go`는 창을 1280×800으로 만들고 HTTP Capture 네이티브 메뉴를 등록한다. macOS에는 50px 숨김 타이틀바 설정이 있어 창 버튼과 드래그 영역을 고려해야 한다.
- `App.tsx`는 기본 프로파일러 화면 왼쪽에 `Sidebar`, 위쪽에는 테마 3개·언어 2개 버튼을 배치한다. `public/style.css`의 사이드바 폭은 224px, 접어도 56px이다. 펼쳤을 때 기본 창 너비의 약 17.5%를 쓴다.
- 프로파일러와 GC 화면에는 입력 도크·옵션과 결과 탭이 함께 있다. HTTP 화면에는 요청 빌더, 라이브 패널, 파일 도크가 있으며 자료를 읽은 뒤 입력 영역을 접는 동작이 이미 있다. 이 패턴을 공통화한다. 아래 수치는 구현 목표이며 실제 네이티브 창에서의 기준선은 T-620에 기록한다.

## 메뉴와 작업 영역

| 메뉴 | 드롭다운 항목 |
|---|---|
| 파일 | 현재 화면에서 열기, 최근 파일, 저장·내보내기 |
| 분석 | 프로파일·비교, 로그·런타임, 트레이스·웹 그룹에서 분석기 선택 |
| 캡처 | HTTP 화면 열기, 시작·일시정지·중지·찾기, 프로세스 그룹 제어 |
| 워크스페이스 | 보관·증거, 시각화·상관분석, 보고서·내보내기 그룹 |
| 보기 | 설정, 테마, 언어, 현재 패널 표시 |
| 도움말 | 현재 화면 도움말, 앱 정보(macOS는 앱 메뉴) |

기본 사이드바와 테마·언어 전용 상단 줄을 없앤다. Windows는 창 메뉴 한 줄, macOS는 시스템 메뉴바를 사용한다. Linux에서는 네이티브 메뉴 노출 여부를 확인하고 필요할 때만 같은 명령의 창 메뉴 한 줄을 제공한다. 화면 안에는 현재 도구명·입력명·자주 쓰는 동작만 한 줄에 둔다. 공간이 부족하면 보조 동작부터 더보기 메뉴로 옮긴다. 화면 이동은 기존 NavKey, 캡처 조작은 기존 명령 라우터를 사용한다. 메뉴와 툴바는 활성 조건을 공유하고 키 입력 한 번에 명령이 한 번만 실행되어야 한다.

예를 들어 HTTP 캡처 창은 다음 순서로 읽힌다.

```text
파일   분석   캡처   워크스페이스   보기   도움말
HTTP 캡처    [시작/중지] [일시정지]   프로세스 ▾   필터   ?
▾ 프로세스 A      메서드    URL                 상태    시간
  요청 1          GET       /orders             200     18 ms
  …               (여기가 남은 높이를 채움)
──────────────── 드래그 가능한 분할선 ────────────────
선택 요청         [헤더] [본문] [타이밍]
Content-Type      application/json
기록 중           요청 수 · 누락 수
```

## 설명과 상태 표시

가까운 라벨 옆에 기존 `HelpTip`의 물음표를 재사용한다. 용어·산식·파일 형식은 마우스를 올리거나 키보드로 포커스하면 표시한다. 클릭 또는 Enter/Space로 고정하고 Esc·바깥 클릭으로 닫는다. 도움말로 포인터를 옮겨도 읽을 수 있게 하며 창 경계와 스크롤 패널에서 잘리지 않도록 위치를 조정한다. 화면별 접근성 이름과 설명 연결을 제공한다. 단계가 많거나 링크가 있는 안내는 도움말 패널에서 열고 닫을 때 원래 버튼으로 포커스를 돌린다.

빈 화면은 파일 열기·놓기 또는 캡처 시작처럼 다음 동작 하나를 안내한다. 결과가 들어오면 입력 선택기는 파일명과 교체 버튼으로 접힌다. 오류·기록 중·누락 건수·부분 데이터·단위·권한 또는 동의가 필요한 상태는 관련 결과나 동작 옆에 계속 표시한다. 원인과 해결 단계만 펼쳐 읽는다.

## 각 기능의 첫 화면

아래는 데이터가 있을 때의 배치안이다. 결과 탭을 바꾸면 선택한 탭의 표나 그래프가 같은 공간을 쓴다. 비어 있는 워크스페이스는 첫 항목을 추가할 방법을, 설정은 즉시 바꿀 수 있는 값을 보여준다.

| 화면 | 첫 화면에 남길 내용 | 필요할 때 열 내용 |
|---|---|---|
| 프로파일러 (`profiler`) | 플레임그래프 또는 상위 프레임, 선택한 스택 경로 | 파일·형식 선택과 분석 옵션 |
| 프로파일 비교 (`diff`) | 증가·감소 프레임과 변화량 | 두 입력 교체·매칭 옵션 |
| GC 로그 (`gc_log`) | 정지 시간 추이와 GC 이벤트 행 | 파일 선택, JVM 환경과 지표 정의 |
| JFR (`jfr`) | 선택 구간의 상위 메서드·스레드 | 입력 옵션과 이벤트 유형 설명 |
| 액세스 로그 (`access_log`) | 요청량·오류·지연 추이 또는 URL 순위 | 파서 설정과 집계 방식 |
| 예외 (`exception`) | 예외 이벤트 목록과 선택 이벤트의 스택 | 시그니처 규칙 설명 |
| 스레드 덤프 (`thread_dump`) | 교착 여부, 경합 스레드·잠금 목록 | 런타임별 세부 옵션 |
| Jennifer MSA (`msa_profile`) | 트랜잭션별 시간 구성과 선택한 호출 | CSV 매핑·파서 보고서 |
| 트레이스 (`trace_import`) | 트레이스·스팬 목록과 선택 경로 | 포맷 감지와 집계 설명 |
| HTTP 캡처 (`http_capture`) | 프로세스별 요청 그리드와 하단 헤더·본문 | 요청 빌더·가져오기·호환성 검사 |
| 브라우저 CPU 프로파일 (`browser_cpu`) | 플레임그래프와 상위 프레임 | 프로파일 가져오기 방법 |
| Lighthouse (`browser_audit`) | 핵심 지표와 개선 항목 목록 | 수집 안내·원본 보고서 메타데이터 |
| 분석 워크스페이스 (`analysis_workspace`) | 보관한 결과 목록과 현재 선택 | 등록 방법·일괄 작업 |
| 내보내기 (`export_center`) | 내보낼 결과·형식·대상 파일/폴더·실행 버튼 | 형식별 상세 설명·추가 옵션 |
| 보고서 비교 (`report_diff`) | 두 보고서 간 변경 행 | 입력 교체·비교 방식 설명 |
| 차트 스튜디오 (`chart_studio`) | 선택 데이터의 차트 캔버스 | 차트 템플릿·렌더러 선택, PNG/SVG/CSV 내보내기 |
| 인시던트 타임라인 (`incident_timeline`) | 시간순 이벤트와 생략 건수 | 그룹화 설명·고급 필터 |
| SLO·골든 시그널 (`slo_golden_signals`) | 목표별 측정값과 판정·미평가 상태 | 목표 편집·산식 |
| 서비스 흐름 (`service_flow`) | 서비스 간 연결과 선택 구간 지표 | 별칭·집계 근거 설명 |
| 증거 보드 (`evidence_board`) | 선택한 증거와 출처 | 보드 사용법·내보내기 옵션 |
| 설정 (`settings`) | 선택 설정 그룹의 값과 변경 동작 | 설정별 배경 설명, 최근 파일 관리, 앱 정보 |

## 완료 판정

- 도움말·메뉴를 닫은 기본 창, 100% 배율, 결과를 불러온 뒤 첫 스크롤 전 상태에서 측정한다. 분모는 OS 창 장식을 제외한 실제 WebView 가시 면적이다. 분자는 실제 WebView 경계로 자른 표 본문·플롯·선택 상세의 합집합이다. 그룹 제목, 가상 스크롤 여분 행, 패널끼리 겹치는 면적을 데이터로 중복 집계하지 않는다. 메뉴·입력 도크·설명·빈 여백은 제외한다. 데이터가 충분한 결과 화면의 목표는 70% 이상이다. 설정·내보내기 폼, 빈 상태, 표본이 적은 결과는 면적 합격률에서 제외하고 그 이유를 기록한다. 이 경우 첫 동작, 필수 입력, 저장·완료 또는 오류 상태가 기본 창에 보이는지 판정한다.
- 행이 충분한 표는 첫 화면에 데이터 행 10개 이상을 온전히 보여준다. HTTP는 그룹을 펼쳐 요청 10행과 선택 상세 4줄을 동시에 표시한다. GC는 정지 추이와 이벤트, 프로파일러는 프레임과 선택 경로를 같은 화면에서 읽게 한다. 차트 중심 탭은 실제 플롯 높이 300 CSS px 이상을 목표로 한다. 글꼴을 축소해 맞추지 않는다.
- 1024×768·125% 배율, 한국어·영어에서도 기본 동작과 도움말을 키보드로 이용할 수 있어야 한다. 표 내부 스크롤을 허용하며 창 전체가 가로로 밀려 명령이나 닫기 버튼이 사라지면 실패다.
- 같은 입력·창 크기·배율·탭으로 전후 스크린샷과 수치를 짝지어 기록한다. 각 화면의 빈 상태와 결과/편집 상태, 해당되는 오류·부분 데이터·선택·도움말 상태를 확인한다. Windows 라이브 캡처는 녹화 중 새 행 도착, 선택 유지, 메뉴 이동 후 복귀까지 실제 앱에서 검증한다. 기존 `verify-windows-live-capture.ps1`의 사이드바 DOM 선택자도 새 탐색 경로에 맞춘다.

## 재점검에서 보완한 동작과 측정 방법

**입력에서 결과까지 (T-620, T-622).** 첫 실행의 프로파일러는 파일 열기와 같은 위치에서의 드롭을 제공한다. 파일 선택 후에는 파일명·분석 실행, 실행 중에는 진행 상태와 지원되는 취소, 성공 후에는 결과·파일 교체를 노출한다. 취소·실패 후에는 선택 파일과 재시도 동작을 되돌려 준다. 프로파일 비교는 두 입력의 역할, 스레드 덤프는 복수 파일의 개수와 순서를 접힌 상태에서도 구분한다. 최근 파일은 필요할 때 열고, 끊어진 경로는 다시 선택할 수 있게 한다. 필터로 결과가 모두 사라지면 적용한 조건과 해제 동작을 함께 표시한다.

**결과 위에 쌓이는 요소 (T-622, T-625, T-626).** 파일 도크의 sticky 헤더와 `AnalyzerOptionsDock`의 세로 버튼을 별도 띠로 남기지 않고 같은 작업 줄로 합친다. 서비스 흐름의 지표 카드 5개처럼 표 위에 나열된 요약은 단위가 있는 짧은 값으로 모은다. 반복 제목·설명은 삭제하고 해석에 필요한 용어만 물음표에 둔다. 중요 발견이나 누락은 해당 값 옆에 남긴다. 첫 결과까지의 거리를 실제로 줄였는지 입력명·조건이 긴 한국어 화면에서도 확인한다. 창을 줄였다가 키우면 표 내부 스크롤과 차트 크기가 새 공간을 사용하고, 선택한 행과 패널 닫기가 계속 보이는지 확인한다.

**메뉴가 실제로 수행할 작업 (T-621).** 프로파일러의 `useShortcuts`에서 열기와 설정 콜백은 현재 비어 있다. Ctrl/Cmd+O는 활성 도구의 파일 선택기, Ctrl/Cmd+,는 설정으로 연결하고 지원하지 않는 명령은 비활성화한다. 현 메뉴의 HTTP 지우기·자동 스크롤도 이관한다. 언어를 바꾸면 네이티브 메뉴 라벨과 현재 선택 표시도 함께 갱신한다. 메뉴를 열고 닫는 동안 현재 페이지를 유지해 선택·스크롤·입력 중인 값이 그대로 돌아오게 한다. 키 입력은 열린 팝업 → 활성 도구 순으로 처리한다. 예를 들어 분석 중 도움말에 Esc를 눌렀을 때 도움말만 닫혀야 한다. macOS에서는 기존 드래그 영역을 대체하고 창 버튼과 새 조작 줄의 클릭 영역을 구분한다. [메뉴와 창](../../apps/engine-native/cmd/archscope-app/main.go) · [프로파일러 단축키](../../apps/engine-native/cmd/archscope-app/frontend/src/hooks/useShortcuts.ts)

**도움말 자체가 화면을 차지하는 문제 (T-622).** 같은 그룹의 반복 설명은 제목 옆 물음표 하나로 모은다. 현재 `HelpTip`은 hover·focus·click이 하나의 열림 상태를 공유한다. ‘호버 → 클릭 → 포인터 이동 → Esc’와 ‘Tab → Enter → Esc’를 각각 검사해 고정한 설명이 유지되고 한 번에 한 층만 닫히게 한다. 기존 옵션 서랍과 최근 파일 목록은 닫힌 상태부터 측정한다. 옵션을 바꿨으면 요약 줄에 적용값 또는 변경 표시를 남긴다. **결과 탭과 분할창 (T-623~T-625).**
- HTTP 일반 보기에는 `100dvh−230px` 높이, 420px 최소 높이, 320px 기본 상세 높이가 있다. 새 툴바 아래 실제 남은 높이로 표와 상세를 나눈다. 26px 요청 10행만으로 260px가 필요하고 그룹 제목·열 제목은 별도다. 최초 기본값에서 측정하고, 저장된 큰 상세 높이로 재실행하거나 창을 줄인 경우에는 양쪽이 보이게 제한한다. 사용자가 조정한 분할선, 선택한 요청·상세 탭, 자동 스크롤 끄기를 유지한다. 캡처 시작 전 수집 범위와 본문 동의, 기록 중 중지, 중지 후 검사까지 각 상태에서 해당 동작을 찾을 수 있어야 한다. [요청 표와 분할창](../../apps/engine-native/cmd/archscope-app/frontend/src/components/HttpAnalyzerView.tsx)
- 프로파일러는 분석 완료 때 현재 요약 탭을 선택한다. 프레임 트리가 있으면 첫 결과에서 그래프와 선택 경로를, 트리가 없으면 상위 프레임이나 이용 가능한 요약을 먼저 보여준다. 얕은 트리는 실제 프레임 가독성으로 판정한다. GC 기본 요약에는 정지 추이와 이벤트 미리보기를 두고 전체 이벤트·힙·JVM 탭을 유지한다. 로그에 시간축이 없으면 관측 가능한 이벤트 목록과 사유를 표시한다. 창 크기를 바꾼 뒤에도 프레임 클릭과 표 행 선택이 화면상의 항목과 일치해야 한다.
- 나머지 기능도 첫 탭만으로 완료 처리하지 않는다. JFR 기록·프로파일·네이티브 메모리, 스레드 덤프 단일·복수 비교, Jennifer MSA 상세, 예외 스택 서랍처럼 입력에 따라 열리는 보기를 목록에 포함한다. 폭이 좁을 때 선택 탭은 보이고 나머지 탭도 키보드나 더보기로 도달할 수 있어야 한다. 긴 URL·스택·파일명은 한 줄 요약하고 상세에서 전체 값을 읽거나 복사하게 한다.

**재현과 완료 증거 (T-620, T-626, T-627).** 화면별로 ‘입력/생성 순서 → 상태·탭 → 첫 데이터까지의 세로 거리(CSS px) → 보이는 전체 행/플롯 높이 → 결과 면적률 또는 폼 판정’을 한 행에 기록한다. 프로파일러와 GC는 각각 [collapsed 예제](../../examples/profiler/sample-wall.collapsed), [GC 예제](../../examples/gc-logs/sample-hotspot-gc.log)로 시작하고, 행 수 검사는 충분한 별도 예제를 전후 동일하게 쓴다. 워크스페이스에서는 결과 등록 → 선택 → 차트·증거·내보내기로 이동하는 경로까지 확인한다. 내보내기의 파일/폴더 선택, 설정의 저장, 형식·단위·출처를 줄인 UI에서도 확인할 수 있어야 한다. 차트 스튜디오에서 템플릿을 바꾸고 창을 조절한 뒤 캔버스와 내보낸 결과를 확인한다.

측정표에 OS, 창 외곽 크기, 실제 WebView 너비·높이(CSS px), 시스템 배율, 언어, 재현 입력과 새/기존 레이아웃 설정을 남긴다. 기존 Windows 검증 스크립트는 WebView의 `nav button.nav-item`을 클릭한다. 새 네이티브 메뉴는 OS 메뉴로 조작하고 현재 화면과 캡처 복귀 결과를 WebView에서 읽는다. Windows 녹화 검증이 가능한 시점과 Mac에서 측정한 결과를 각각 기록한다. 결과 면적이 늘어도 입력 열기·분석 취소·선택 상세를 사용할 수 없으면 해당 화면은 미완료다.

## 2026-11-10 구현과 저녁 확인

T-621~T-626의 코드 구현은 개별 커밋에 반영했다. 네이티브 메뉴와 단축키,
입력·옵션·도움말, HTTP 분할창, GC 요약과 프로파일러 첫 탭, 나머지 분석기와
워크스페이스 배치를 적용했다. 파일 드롭은 각 도구의 파일 선택 영역에서 받는다.
도구를 이동하면 기존처럼 해당 페이지를 다시 마운트하고, HTTP 기록은 서비스에서
복원한다. 메뉴를 열고 닫는 동안에는 현재 페이지를 유지한다.

Mac 잠금 상태의 네이티브 수집 시도에서 준비 보고서가 생성되지 않았다.
사용자는 2026-11-10 저녁 잠금 해제 후 실제 화면을 확인하기로 했다.
T-620의 원본 UI 측정과 T-627의 실제 UI 검증이 남아 있어 T-621~T-626은
REVIEW로 관리한다. 결과 면적 70%와 HTTP 10행/상세 4줄은 실측 전이다.

저녁에는 다음 순서로 확인한다.

1. `apps/engine-native/cmd/archscope-app/bin/archscope.app`을 열고 첫 실행에서
   21개 메뉴로 이동한다. 파일 열기·최근 파일·설정·테마·언어·앱 정보를 확인한다.
2. 설계의 창 크기·배율·언어별로 실제 결과를 불러와 측정표를 채운다.
   기준선 코드는 `d98a958` 커밋에 있고 개선본은 현재 HEAD다.
   별도 체크아웃과 같은 예제로 전후를 비교한다. 기본 `measure.js`는 초기 화면
   수집용이며 입력을 분석하거나 세부 탭을 자동으로 채우지 않는다.
3. `?` 호버·고정·포인터 이동·Esc와 옵션 서랍 닫기, 창 가장자리 잘림,
   긴 경로·빈 결과·오류·필터 해제를 점검한다.
4. GC의 정지 추이·이벤트와 프로파일러 드릴다운을 확인하고 창을 줄였다가
   키운 뒤에도 선택 위치와 표·그래프가 일치하는지 확인한다.
5. HTTP는 저장 파일을 열어 표·상세 탭·분할선을 확인한다. Windows에서는
   실제 캡처 중 요청 도착, 프로세스 선택, 자동 스크롤 끄기, 메뉴 이동 후 복귀를 확인한다.

`verify-windows-live-capture.ps1`의 재진입 검사는 새 화면 라우팅을 사용한다.
OS 메뉴를 실제 클릭하는 검사는 별도로 수행한다. 기존 미추적 로컬
`verify-http-desktop.mjs`는 예전 사이드바 구조를 기대하므로 새 UI 확인에
사용하기 전에 갱신해야 한다.


## Mac 네이티브 검증 및 보완 (2026-11-10 저녁)

Wails 3.1.0 검증 전용 앱의 실제 macOS 메뉴와 파일 선택기를 사용했다.
브라우저·Electron은 실행하지 않았다. 21개 화면의 메뉴 이동과 전체 너비를
확인했고, 프로파일러·GC·액세스 로그·JFR·예외·스레드 덤프·Jennifer·Trace·
브라우저 CPU·Lighthouse·HAR를 파일로 분석했다. 비교, 워크스페이스 전달,
증거 추가, HTML 내보내기, 설정 저장, 언어·테마·앱 정보도 확인했다.

검증 중 발견해 수정한 항목은 다음과 같다.

- 공통 컨테이너가 내용 너비만 사용해 프로파일러가 창 절반에 그려지던 문제를 수정했다.
- HTTP의 세션 설명이 기본으로 펼쳐져 요청 행을 밀어내던 문제를 수정했다.
  캡처 버튼은 한 줄로 배치하고 세션 도구·열 필터·파일 도구는 필요할 때 펼친다.
- 도움말을 마우스로 고정한 후 포커스가 다른 곳에 있으면 Esc로 닫히지 않던 문제와,
  닫힌 도움말이 Esc를 가로채던 문제를 수정했다. 상세 창 최초 포커스는 닫기 버튼이다.
- 파일 선택 영역의 중첩 버튼 역할을 제거해 찾아보기·도움말·지우기를 별도 조작으로 노출했다.
- 액세스 로그는 URL, Trace는 Trace 목록을 기본 탭으로 열고 Lighthouse 메타데이터와
  카테고리 설명 및 프로파일러 진행 로그는 접힌 상태로 시작한다.
- 데스크톱 진행 로그가 서명된 앱 번들 안에 기록되던 문제를 수정했다.
  기본 경로는 사용자 캐시의 `ArchScope/logs`이며 명시한 경로는 유지한다.
- 측정기가 npm 번들에 없는 `window.wails`를 가정하던 문제도 수정했다.
  앞선 보고서 미수집은 잠금 상태뿐 아니라 이 결함의 영향도 있었으므로,
  이전 실행은 여전히 미완료 증거로 남긴다.
